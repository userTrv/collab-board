Go offline, edit the same cards differently on both sides, then reconnect: the CRDT merges them deterministically, with no server and no “conflict” dialog.

Why doesn’t anything get lost or duplicated?
  • Entities are keyed by id in Y.Maps, not stored in arrays. A move writes the card’s columnId and fractional rank fields — concurrent moves can’t duplicate the card, the last writer decides where it lands.
  • Same field, concurrent writes: Yjs keeps one value, chosen identically on every replica (causal order, then client id).
  • Delete vs. edit: writes into a deleted Y.Map are ignored, so a deleted card never comes back half-edited.
  • Text (descriptions) is a Y.Text: concurrent typing interleaves character by character.
  • Reconnect exchanges state vectors and sends only the missing updates — the same sync step 1/2 that the real app runs over BroadcastChannel between tabs.
